Стратегия ветвления: GitHub Flow

Принцип именования веток:
<Тип>/<US-номер>-<краткое-описание>, где
Тип = тип изменений
US-номер = номер реализуемой истории пользователя
Краткое-описание = описание того, что реализуется

Пример: Фича/US-4-Авторизация-Форма

Типы
Фича: новая функциональность
Фикс: исправление бага
Перепись: изменение кода без изменения поведения
Тест: добавление или проверка тестов
Оболочка: конфиг, зависимости, CL

Жизненный цикл ветки: 2-3 дня

Правила слияния:
1. Pull Request - почти всегда единственный способ внесения изменений в MAIN
2. Размер Pull Requset: желательно не более 200 строк, максимум 400 строк. Выход за максимум = дробление Pull Request на несколько более меньших
3. Описание Pull Requset должно содержать описание изменений, ссылку на юзер стори. Для интерфейса прикрепить скрин изменений(было, стало).
